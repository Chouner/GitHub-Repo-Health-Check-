1、拆分需求
核心功能： 用户输入一个公开 GitHub 仓库 URL，例如：https://github.com/xxx，系统自动分析该仓库，并在 Web 页面中展示： 
•  基础信息：名称、描述、作者、创建时间、更新时间  
•  热度指标：Star、Fork、Watch、Issues、Pull Requests  
•  活跃度指标：最近提交、最近 Release、最近更新时间  
•  代码结构：语言分布、目录结构、文件数量  
•  社区健康度：Issue 关闭率、PR 合并情况、贡献者数量 
•  文档质量：README、LICENSE、CONTRIBUTING、CHANGELOG 是否存在  
•  AI 项目评分：从维护活跃度、社区热度、工程规范、文档质量、可持续性等维度评分

3、模块拆解
（1）基础模块
模块 功能 优先级   
URL 输入 用户输入 GitHub 仓库 URL P0 
URL 解析 提取 owner 和 repo P0  
GitHub API 拉取 获取仓库基础信息 P0  
指标展示 Star、Fork、Issue、语言分布 P0  
图表可视化 饼图、卡片、雷达图或柱状图 P0  
AI 评分 调用大模型或本地规则生成评分 P1  
报告展示 生成仓库体检报告 P1         
（2）额外模块 
模块 功能 价值   
README 分析 读取 README 内容，判断文档质量 高  
LICENSE 检测 判断是否有开源协议 中  
Contributors 分析 展示主要贡献者 中  
Commit 活跃度 展示近 30 天提交趋势 高 
 Issue 健康度 开放 Issue、关闭
 Issue、响应情况 高  
AI 建议 给出改进建议 高  
分享报告 生成可复制的 Markdown 报告 中
4、评分模型设计
AI 评分可以分两层：
（1）规则评分
先用规则算一个基础分，保证即使 AI API 不可用，也能展示评分。
总分 100：
维度	权重
社区热度	25
维护活跃度	25
文档完整度	20
工程规范	15
生态成熟度	15
（2）评分规则示例
社区热度，25 分
Stars > 10000：25
Stars > 1000：20
Stars > 100：12
Stars <= 100：6
维护活跃度，25 分
最近 7 天有更新：25
最近 30 天有更新：20
最近 90 天有更新：12
